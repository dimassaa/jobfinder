# AGENTS.md — Инструкции для OpenCode Agent

## Общее описание проекта
Ты работаешь над курсовым проектом **"Приложение для учёта обращений в службу занятости с модулем анализа вакансий"**.
- Архитектура: клиент-сервер, многопоточный сервер (Java 21), клиент на JavaFX.
- Взаимодействие: TCP/IP сокеты, JSON (Jackson).
- БД: PostgreSQL (контейнеризация через Docker).
- Сборка: Maven (многомодульный проект: common, server, client).
- Логирование: Logback.
- Тестирование: JUnit 5, Mockito, Testcontainers.

## Основные файлы-инструкции (читать обязательно)
При выполнении любого шага обращайся к следующим файлам за контекстом:
- @Техническая часть — общая архитектура и технологии.
- @Требования — функциональные и нефункциональные требования.
- @Указания по javaFX — **строго соблюдать** при разработке визуальной части.
- @Юз кейсы и этапы финал — полный список сценариев использования, распределённых по ролям.

## Файлы с пошаговым планом
Проект разбит на этапы. Для каждого этапа существует отдельный файл с детализацией шагов.  
**При работе над конкретным шагом читай соответствующий файл:**
- Этапы 1.1 – 3.10 → @Шаги 1.1 - 3.10
- Этапы 4.1 – 5.10 → @Шаги 4.1 - 5.10
- Этапы 6.1 – 7.10 → @Шаги 6.1 - 7.10
- Этапы 8.1 – 9.10 → @Шаги 8.1 - 9.10
- Этапы 10.1 – 10.10 → @Шаги 10.1 - 10.10

Каждый файл содержит описание шагов с указанием конкретных действий, создаваемых классов, методов и способов проверки.

## Режим работы — **СТРОГО ОДИН ШАГ ЗА СЕССИЮ**
Ты выполняешь **только один шаг** из плана, указанный пользователем в запросе.  
**Не переходи к следующему шагу**, даже если кажется логичным продолжить. После завершения шага — остановись и предоставь отчёт.

## Порядок выполнения одного шага
1. **Прочитай** описание шага в соответствующем файле этапов.
2. **Изучи** необходимые классы/файлы из предыдущих шагов, если они упоминаются и файл @Юз кейсы и этапы финал на случай общих правок.
3. **Внеси изменения** в код строго в соответствии с описанием шага:
   - Создай новые классы / методы.
   - Обнови зависимости в `pom.xml` (модулей), если требуется.
   - При работе с JavaFX следуй @Указания по javaFX.
4. **Запусти тесты**, ТОЛЬКО связанные с данным шагом (модульные и интеграционные). Убедись, что они проходят.
5. **Проверь сборку**: `mvn clean package` должен завершаться успешно.
6. **Проверь Docker**: если шаг затрагивает сервер или БД, убедись, что `docker-compose up` работает.
7. **Сделай Git-коммит** с сообщением формата:  
   `[Номер этапа] Краткое описание`  
   (например, `Этап 4.5: Создание UserService и обработчиков профиля`)
8. **Напиши отчёт** в ответе, содержащий:
   - Список созданных/изменённых файлов.
   - Краткое описание выполненных действий.
   - Результаты тестов (пройдены / ошибки и их исправление).
   - Возникавшие в процессе выполнения проблемы и как ты их решил (если такие были).
   - Подтверждение успешной сборки и работы Docker (если применимо).

## Важные правила
- **Не выходи за рамки текущего шага.** Если требуется изменить файлы из предыдущих шагов — делай это только если явно указано в описании шага.
- **Не меняй архитектуру** без необходимости. Придерживайся уже определённых пакетов и соглашений.
- **Используй Java 21** (проверь версию в `pom.xml` и `Dockerfile`).
- **Логируй** важные события через Logback.
- **Тесты** — обязательная часть каждого шага, где они предусмотрены.
- **ВСЕ ДАННЫЕ ДОЛЖНЫ БЫТЬ ДЛЯ БЕЛАРУСИ**
