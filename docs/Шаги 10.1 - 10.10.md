## Этап 10: Администрирование, восстановление пароля, безопасность, Docker production

### 10.1 Создание DTO для административных функций

- **Файлы (в модуле `common`):**
  - `AdminUserDto.java` – поля: `id`, `email`, `role`, `name`, `surname`, `city`, `isBlocked`, `blockedUntil`, `createdAt`.
  - `BlockUserRequest.java` – поля: `userId`, `reason`, `durationHours` (null для постоянной).
  - `ComplaintAdminDto.java` – расширяет `ComplaintDto`, добавляет данные о цели (название вакансии/имя пользователя).
  - `ResolveComplaintRequest.java` – поля: `complaintId`, `action` (DISMISS, BLOCK_VACANCY, BLOCK_USER).
  - `AddTagRequest.java` – поле: `tagName`.
- **Проверка:** Компиляция и JSON-сериализация.

### 10.3 Создание таблиц password_reset_tokens и block_history (если ещё нет)
- **Что делаем:** Обновляем `init.sql` (или создаём миграцию) для добавления недостающих таблиц.
- **SQL-скрипт (добавление):**
  ```sql
  CREATE TABLE IF NOT EXISTS password_reset_tokens (
      id SERIAL PRIMARY KEY,
      user_id INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
      token VARCHAR(255) NOT NULL UNIQUE,
      expires_at TIMESTAMP NOT NULL,
      created_at TIMESTAMP DEFAULT NOW()
  );

  CREATE TABLE IF NOT EXISTS block_history (
      id SERIAL PRIMARY KEY,
      user_id INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
      blocked_by INT NOT NULL REFERENCES users(id),
      reason TEXT,
      blocked_until TIMESTAMP,
      created_at TIMESTAMP DEFAULT NOW()
  );
  ```
- **Проверка:** Перезапустить Docker Compose, убедиться, что таблицы созданы.

### 10.5 Реализация сервиса восстановления пароля (PasswordResetService)
- **Что делаем:** Сервис, генерирующий токен, отправляющий email и сбрасывающий пароль.
- **Файл:** `server/service/PasswordResetService.java`
  - Зависимости: `UserRepository`, `PasswordResetTokenRepository`, `EmailService` (заглушка или реальный SMTP).
  - Методы:
    - `void requestPasswordReset(String email)`
      - Проверяет существование пользователя.
      - Генерирует `UUID` токен.
      - Сохраняет в `password_reset_tokens` с `expires_at = now + 24h`.
      - Отправляет email через `EmailService.send(email, "Password Reset", "Your token: " + token + " or link: http://localhost:8080/reset?token=" + token)`.
    - `void resetPassword(String token, String newPassword)`
      - Проверяет токен (существует, не истёк).
      - Получает пользователя, хеширует новый пароль, обновляет.
      - Удаляет использованный токен.
- **EmailService:** Реализуем простую заглушку, которая пишет в лог (для демонстрации). При желании можно подключить JavaMail с фейковым SMTP (например, MailHog в Docker).
- **Проверка:** `PasswordResetServiceTest` с моками репозиториев и `EmailService`.

### 10.6 Создание AdminService с бизнес-логикой администрирования
- **Что делаем:** Сервис, объединяющий все операции администратора.
- **Файл:** `server/service/AdminService.java`
  - Методы:
    - `List<AdminUserDto> getAllUsers(String roleFilter, Boolean blockFilter, int page, int size)`
    - `void blockUser(int userId, int adminId, String reason, Integer durationHours)`
      - Вычисляет `blockedUntil`, вызывает `userRepository.blockUser()`, создаёт запись в `block_history`.
      - Если пользователь онлайн – закрыть его сессию через `SessionManager`.
    - `void unblockUser(int userId)`
    - `void deleteUser(int userId)`
    - `List<VacancyDto> getAllVacancies(boolean includeInactive)`
    - `void deleteVacancy(int vacancyId)`
    - `List<ComplaintAdminDto> getComplaints()`
    - `void resolveComplaint(int complaintId, String action, int adminId)`
      - Если `BLOCK_VACANCY` – деактивировать вакансию.
      - Если `BLOCK_USER` – заблокировать автора вакансии/жалобы.
    - `void addTag(String name)`
    - `void deactivateTag(int tagId)`
- **Проверка:** `AdminServiceTest` с моками.

### 10.7 Реализация серверных обработчиков для административных команд и восстановления пароля
- **Что делаем:** Добавляем команды в `ClientHandler` (или паттерн Command).
- **Команды:**
  - `FORGOT_PASSWORD` (email) → вызывает `passwordResetService.requestPasswordReset()`.
  - `RESET_PASSWORD` (token, newPassword) → вызывает `passwordResetService.resetPassword()`.
  - `GET_ALL_USERS` → `adminService.getAllUsers()`.
  - `BLOCK_USER` → `BlockUserRequest`.
  - `UNBLOCK_USER` → userId.
  - `DELETE_USER` → userId.
  - `GET_ALL_VACANCIES_ADMIN` → includeInactive.
  - `DELETE_VACANCY_ADMIN` → vacancyId.
  - `GET_COMPLAINTS_ADMIN` → `adminService.getComplaints()`.
  - `RESOLVE_COMPLAINT` → `ResolveComplaintRequest`.
  - `ADD_TAG` → tagName.
  - `DEACTIVATE_TAG` → tagId.
- **Безопасность:** Все команды должны проверять роль `ADMIN` в текущей сессии. Для `FORGOT_PASSWORD` и `RESET_PASSWORD` аутентификация не требуется.
- **Проверка:** Интеграционные тесты с отправкой команд.

### 10.9 Усиление безопасности: проверка ролей во всех обработчиках, валидация входных данных
- **Что делаем:** Проходим по всем обработчикам команд и добавляем аннотации или ручные проверки ролей.
- **Реализация:**
  - В каждом обработчике (или в диспетчере) вызывать метод `checkRole(userId, requiredRoles)`.
  - Для гостевых команд (поиск вакансий, регистрация, вход) проверка не требуется.
  - Добавить валидацию DTO на сервере: проверка на null, длина полей, формат email.
  - Убедиться, что все SQL-запросы используют `PreparedStatement` для защиты от инъекций.
- **Проверка:** Написать тесты, пытающиеся выполнить административные команды от имени обычного пользователя – должны возвращать ошибку доступа.

### 10.10 Финальная сборка Docker, healthcheck и документация
- **Что делаем:** Доводим контейнеризацию до production-ready состояния.
- **Шаги:**
  - **Dockerfile для сервера (multi-stage):**
    ```dockerfile
    FROM maven:3.9-eclipse-temurin-21 AS build
    WORKDIR /app
    COPY pom.xml .
    COPY common/pom.xml common/
    COPY server/pom.xml server/
    RUN mvn -pl server -am dependency:go-offline
    COPY . .
    RUN mvn -pl server -am clean package -DskipTests

    FROM eclipse-temurin:21-jre-alpine
    WORKDIR /app
    COPY --from=build /app/server/target/server-*.jar app.jar
    EXPOSE 8080
    ENTRYPOINT ["java", "-jar", "app.jar"]
    ```
  - **docker-compose.yml (финальный):**
    ```yaml
    version: '3.8'
    services:
      postgres:
        image: postgres:15
        environment:
          POSTGRES_DB: jobdb
          POSTGRES_USER: jobuser
          POSTGRES_PASSWORD: secret
        volumes:
          - ./db/init.sql:/docker-entrypoint-initdb.d/init.sql
          - pgdata:/var/lib/postgresql/data
        healthcheck:
          test: ["CMD-SHELL", "pg_isready -U jobuser"]
          interval: 5s
          timeout: 5s
          retries: 5

      server:
        build:
          context: .
          dockerfile: server/Dockerfile
        ports:
          - "8080:8080"
        environment:
          DB_HOST: postgres
          DB_PORT: 5432
          DB_NAME: jobdb
          DB_USER: jobuser
          DB_PASSWORD: secret
        depends_on:
          postgres:
            condition: service_healthy
        healthcheck:
          test: ["CMD", "curl", "-f", "http://localhost:8080/health"]  # если есть health endpoint, иначе просто проверка порта
          interval: 10s
          timeout: 5s
          retries: 3

    volumes:
      pgdata:
    ```
  - **Добавление простого health endpoint на сервере:**
    - Команда `HEALTH` возвращает `Response` со статусом OK.
  - **Документация:** Обновить `README.md` с инструкциями по запуску `docker-compose up`, описанием переменных окружения.
- **Проверка:** Выполнить `docker-compose down -v && docker-compose up -d`. Убедиться, что оба контейнера здоровы, сервер доступен на порту 8080, клиент может подключиться и работать.
